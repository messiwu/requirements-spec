# 需求专家

[INFERRED] 目标是让架构、开发、测试可以依据同一版需求判断业务结果，同时保留技术实现空间。识别原始陈述、证据、推导、建议与采纳状态；未经授权的新业务选择保持为建议或待决定。

## 识别当前任务

| 用户请求 | 入口 |
|---|---|
| 补全已有 PRD | 先逐项还原原意，找冲突、遗漏与无法验收的表述，再成文 |
| 只有一句话或口述 | 先确定用户任务、结果和本期范围，再细化需求 |
| 多份材料相互冲突 | 先定位来源及结果差异，按有效决定裁决或保留待决定 |
| 只要求评审 | 输出有定位、反例、影响和最小修复的报告；遵守用户给定的编辑范围 |
| 已有基线需要变更 | 区分候选提案与已采纳变更，分析受影响切片及生效条件 |
| 要求给当前项目接入方法 | 检查现有 `AGENTS.md`，按下面的接入步骤加入项目入口 |

## 读取与执行

资源路径相对于本 `SKILL.md` 所在目录解析，与项目工作目录无关。技能已携带方法与模板，无需让用户再提供方法路径、复制模板或填写通用初始化信息。参考手册中的手动准备步骤仅供未安装技能时使用。

1. 读取本次业务材料与项目现有约定。材料不可读时说明缺什么，继续不依赖它的部分。
2. 读取 [agent 工作规程](references/02-agent工作规程.md)。首次使用或需求边界不清时读取 [设计依据与边界](references/01-设计依据与边界.md)。
3. 根据任务选择材料：成文时读取 [需求规格模板](references/模板/01-需求规格.md)、[依据与决策模板](references/模板/02-依据与决策.md)及[验收与追溯模板](references/模板/03-验收与追溯.md)；准备交接时再读[交接索引模板](references/模板/00-交接索引.md)。仅评审时先读[质量审查与交接](references/03-质量审查与交接.md)。出现企业协作、消费产品或智能体执行等真实机制时，读取[场景扩展与配图](references/04-场景扩展与配图.md)。
4. 以用户任务为主线推进。自己能核实的事实先核实；会改变业务承诺且未获授权的选择，提出方案与影响并保留待决定。已有明确授权的事项直接处理，继续不依赖未决项的工作。
5. 成文时形成交接索引、需求规格、依据与决策、验收与追溯四种逻辑视图。小需求可以合并，大需求可按业务能力拆分。用户只要评审时，交付评审报告即可。
6. 按[质量审查与交接](references/03-质量审查与交接.md)检查原始请求去向、主路径、高影响异常、竞争解释与验收判定。报告实际检查、开放问题及按切片确定的需求侧状态。

[INFERRED] 项目已有需求目录时沿用其结构；无约定时，将本次需求产物放在项目的 `docs/requirements/<需求主题>/`。该路径是默认组织位置，不要求把本技能或模板复制进每个项目。用户指定目录或仅要求在聊天中回答时，遵照本次请求。

## 项目接入

[INFERRED] 本技能全局安装后，个人使用无需项目初始化。只有用户要求把方法写进某个项目的规则、供仓库内其他 agent 使用时，才添加项目级入口。

1. 确认用户指定的项目根目录，检查该项目及上级适用的 `AGENTS.md`；保留原有内容。
2. 检查是否已有等效的需求方法入口。有则不重复添加，并报告实际规则位置。
3. 需要新增时，使用[项目规则片段](assets/AGENTS-项目片段.md)；将本 `SKILL.md` 所在的绝对目录作为〈技能目录〉，运行 `python3 "〈技能目录〉/scripts/configure_project.py" "〈项目根目录〉"` 进行幂等写入。项目目录明确后由 agent 执行，无需让用户手工运行。脚本只管理带标记的这一小段，不改其他规则。
4. 读回项目 `AGENTS.md`，确认原规则保留、入口只出现一次。项目接入不自动创建业务需求文档；具体需求到来后再按任务执行。

[COMMON] 仓库级规则能向使用该仓库的 agent 提示调用本技能；其他机器仍需安装或提供本技能，单独的规则片段不包含完整方法。
