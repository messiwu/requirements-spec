# 〈需求主题〉依据与决策

[INFERRED] 模板说明：保存会影响需求含义、效力与版本的依据。表格可合并，小需求可以用带编号的段落；不必为普通连接语创建记录。稳定编号在当前需求包内唯一，删除条目后不重用。

基线版本：〈与交接索引一致〉。

## 3. 决定记录

### DEC-〈编号〉 〈具体决定〉

- 问题与来源：〈为什么需要选择，关联来源或问题〉。
- 选项与差异：〈可行选择及业务后果〉。
- 采用结论：〈具体行为及适用范围〉。
- 理由与代价：〈为什么选择它，接受了什么限制〉。
- 决策者与授权依据：〈真实确认记录，或 agent 已获授权的范围〉。
- 状态及时间：〈待决定／已采纳／已否决／已取代〉。
- 影响：〈需求、规则、流程、字段、图、验收和依赖〉。
- 取代关系：〈无或旧决定编号〉。

|---|---|---|---|---|---|---|---|

〈冲突以会产生不同业务结果的具体场景说明。材料时间更新不自动意味着拥有更高决策权限；按已知效力和授权裁决，不明时保留冲突。〉

〈事实核实不必创建业务决定；方案选择不得只靠“已核实”代替授权。候选变更不自动改变现行基线，已采纳变更需写明新版本的生效条件。〉
